# Мебель-Сервис

Сайт ООО «Мебель-Сервис» на Next.js 16 (App Router, TypeScript).

## Запуск

Локально:

```bash
npm install
cp .env.example .env.local   # заполнить перед боевым запуском
npm run dev                  # http://localhost:3000
npm run build
npm start
```

Боевой сервер в РФ — через Docker (SQLite в томе, Caddy на 80/443):

```bash
cp .env.example .env         # TELEGRAM_*, INBOX_PASSWORD, DOMAIN=meb-srv.ru
docker compose up -d --build
```

Заявки и заказы пишутся в том `mebel-data`. Служебная лента: `https://meb-srv.ru/inbox`.
`NEXT_PUBLIC_SITE_URL` и `NEXT_PUBLIC_YANDEX_METRIKA_ID` задаются на этапе сборки образа.

## Перед запуском в бой

1. **Почта.** Без переменных `SMTP_*` формы отвечают «принято», но уведомление
   остаётся только в служебной ленте и логе сервера. Настройки — в
   [.env.example](.env.example).
2. **Заглушки в текстах.** Тарифы, сроки и минимальные партии на страницах доставки,
   оплаты и опта помечены плашкой «уточнить» и видны прямо на странице.
   Найти все: `grep -rn "<Todo" src/`
3. **Адрес сайта.** `NEXT_PUBLIC_SITE_URL` попадает в `sitemap.xml`, `robots.txt`,
   микроразметку и превью для соцсетей.
4. **Метрика.** Счётчик подключается только при заданном `NEXT_PUBLIC_YANDEX_METRIKA_ID`.
5. **Мессенджеры.** Ссылка на WhatsApp построена на основном телефоне — проверьте,
   что он действительно подключён. Аккаунт Telegram пока не указан:
   [src/data/contacts.ts](src/data/contacts.ts).

## Заявки

Заявки и заказы сохраняются в SQLite на сервере и видны в служебной ленте
`/inbox` под паролем. Уведомление сотрудникам уходит **на почту**.

В письме нет ни имени, ни телефона — только номер заявки, источник и ссылка
на ленту. Персональные данные не покидают сервер в РФ, поэтому письмо можно
слать через внешний релей.

### Почему релей, а не smtp.mail.ru

С сервера закрыты порты 25, 465 и 587 — антиспам-политика хостинга. Открыт
2525, на нём работают релеи почтовых сервисов (Brevo, Mailgun, SendGrid,
Resend, SMTP.bz). Настройки задаются переменными `SMTP_*` в `.env`, код
провайдер-независимый: если хостинг откроет 465, туда же подойдёт
`smtp.mail.ru` с обычным ящиком.

### Telegram сейчас не работает

`api.telegram.org` с сервера недоступен. Канал оставлен в коде и молчит,
пока не заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`; на запрос стоит
таймаут 8 секунд, чтобы недоступность не подвешивала отправку формы.

## Каталог

Разделы — статические маршруты `/catalog/[cat]`, каждый получает только свои товары.
`/catalog` отдаёт весь список. Фильтрация, сортировка и поиск идут на клиенте без запросов
к серверу, показ постранично по 24 позиции.

Фильтры: раздел, цена, цвет, габариты, нагрузка, покрытие, метка и «только по ГОСТ».
Поиск — по названию, артикулу, материалу, габаритам, цветам и ГОСТ; поддерживает `/catalog?q=`.

Устройство панели ([src/components/catalog](src/components/catalog)):

- `filters.ts` — чистая логика: предикат, счётчики граней, границы диапазонов, разбор
  применённых фильтров в плашки. Внутри одной грани значения складываются по «или»,
  разные грани — по «и».
- Рядом с каждым вариантом стоит число: сколько позиций останется, если его выбрать.
  Считается «как будто эта грань не применена», иначе выбор обнулял бы соседей.
  Варианты с нулём гаснут, но не исчезают — так видно тупики.
- Применённые фильтры показаны плашками над сеткой, каждая снимается по отдельности.
- Группы свёрнуты в аккордеоны; на экранах уже 980px панель уезжает в шторку с кнопкой
  «Показать N». До этого на телефоне до первого товара было 1386px чистых фильтров.

## Данные каталога

Исходные описания товаров — сплошной текст в поле `desc`. Характеристики оттуда разбирает
[scripts/enrich-catalog.mjs](scripts/enrich-catalog.mjs) в отдельные поля:

```bash
node scripts/enrich-catalog.mjs --dry   # посмотреть, что получится
node scripts/enrich-catalog.mjs         # записать в src/data/catalog.json
```

Скрипт идемпотентен и заполняет: вес (682 товара), объём упаковки (419), нагрузку (259),
покрытие (210), гарантию (179), страну (172), спальное место (78) и ГОСТ (58).

Заодно он нормализует то, что иначе разваливает фильтры:

- **Покрытие** — 14 написаний сводятся к трём значениям.
- **Гарантия** — «1 год», «12 месяцев» и просто «1» приводятся к месяцам.
- **Цвет** — исходные 113 значений превращаются в 57 тегов `colorTags`. Схлопывается
  регистр, разбираются составные описания («М/К - серый, ЛДСП - Ольха» → «Серый», «Ольха»),
  вырезаются коды RAL и слова про фактуру, чинятся латинские буквы вместо кириллических
  («Cерый» с латинской C был отдельным значением фильтра). Исходная строка остаётся
  в `colors` — она нужна в характеристиках товара.

Ещё один скрипт, [check-middleware-categories.mjs](scripts/check-middleware-categories.mjs),
сверяет захардкоженный в middleware список разделов со справочником — список продублирован
намеренно, чтобы не тащить в middleware JSON на 1,1 МБ.

Остальные скрипты в `scripts/` — одноразовые скрейперы с metmebel.ru, написанные под старый
`js/data.js`, которого больше нет. Для повторного сбора их нужно перенастроить на JSON.

## SEO

`sitemap.xml` и `robots.txt` генерируются из каталога. Микроразметка: `Organization` и `WebSite`
в корневом layout, `Product` и `BreadcrumbList` на карточке товара.
